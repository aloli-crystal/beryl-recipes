= Changelog
:toc: left

Toutes les modifications notables de ce dépôt de recettes sont
documentées dans ce fichier. Une entrée par recette ajoutée,
modifiée ou retirée.

Le format s'inspire de https://keepachangelog.com/fr/1.1.0/[Keep a Changelog].

Versionnage par tags git aligné sur les jalons beryl :

* `v0.x.y` — phase 0/1, recettes en cours de stabilisation, format
  YAML pas encore figé.
* `v1.0.0` — tronc commun rodé, format figé, recettes documentées
  et testées.

== 0.0.35 (14 octobre 2026)

=== Corrigé

* `root-password-lock` — la commande tient sur UNE ligne (lignes du bloc
  `>-` au même niveau) : indentées, elles gardaient leurs retours à la ligne
  et le shell de connexion csh refusait `sudo sh -c '…'` (« Unmatched ' »,
  qwerty). Avec beryl >= 0.6.31, un script multi-ligne passe de toute façon ;
  la recette reste sur une ligne pour fonctionner aussi avec un beryl plus
  ancien.

== 0.0.34 (14 octobre 2026)

=== Ajouté

* `root-password-lock` — verrouille le mot de passe de `root` et `toor`
  (champ à `*`) : une installation FreeBSD laisse `root` sans mot de passe,
  donc `su` sans rien taper pour tout membre de `wheel`. `sudo` et l'accès
  root par clé SSH restent possibles (`*` n'est pas `*LOCKED*`). Un mot de
  passe déjà en `*…` est laissé tel quel. Requiert beryl >= 0.6.26
  (primitive `command`).

=== Modifié

* `ssh-hardening` — requiert `root-password-lock` : le durcissement de
  l'accès au serveur verrouille aussi le mot de passe root (donc dès le
  bootstrap, qui enchaîne `apply`).

== 0.0.31 (14 octobre 2026)

Requiert beryl >= 0.6.26 (primitives `command`, `file-absent`, `postgresql-*`,
options `if_changed` / `deferred`, `requires:` en forme map).

=== Ajouté

* `nginx-base` — socle nginx commun, SEULE recette à écrire `nginx.conf` :
  paquet (`nginx-lite` par défaut, `nginx` plein au choix), durcissement
  commun, `:80` par défaut (défis ACME pour tous les noms + redirection
  HTTPS), `:443` par défaut en `ssl_reject_handshake` (aucun certificat
  exposé pour un nom inconnu), `include conf.d/*.conf;` (un fichier par site)
  et `http_extra` (directives ajoutées au bloc http). Surveille le processus
  nginx (`monit.d/nginx.conf`) et retire les anciennes sondes qui
  déclaraient chacune `check process nginx` (beryl >= 0.6.26 : `file-absent`).
  Bascule de variante : toute AUTRE variante nginx installée (nginx,
  nginx-lite, nginx-lite-passenger-ruby<NN>, nginx-globex…) est retirée avant
  d'installer `package`, et nginx est redémarré s'il tournait (étape `command`
  gardée, en lecture seule à blanc).

=== Modifié (refonte nginx conf.d)

* Rechargement de monit en `deferred: true` (beryl >= 0.6.26) dans `monit`,
  `nginx-base`, `poudriere-nginx`, `static-site-https`, `zfs-scrub` : un seul
  rechargement, donc une seule alerte « instance changed », par apply.

* `static-site`, `static-site-https`, `poudriere-nginx` — déposent leur
  fichier dans `/usr/local/etc/nginx/conf.d/` au lieu d'écrire `nginx.conf`
  (requires `nginx-base`) : plusieurs sites et recettes web cohabitent sur un
  même serveur. Sondes monit par site (`monit.d/https-<nom>.conf`,
  `poudriere-repo.conf`, `check host`), le processus nginx étant surveillé
  par nginx-base. `static-site` : nom principal + `server_aliases`.
  `poudriere-nginx` générique : DNS-01 aux conventions du port acme.sh (plus
  de geste manuel ni de chemin `/usr/local/etc/ssl/acme`), paramètre
  `public_ip` retiré (écoute sur toutes les adresses, noms inconnus pris par
  les serveurs par défaut).

=== Modifié

* `static-site`, `static-site-https` — paramètre `server_extra` : directives
  ajoutées telles quelles dans le bloc `server` du site (ex. un `location`
  propre à un serveur), renseignées dans le host.yml — la recette reste
  générique et rien n'est perdu au prochain apply.
* Rechargements conditionnels (`if_changed: true`, beryl >= 0.6.26) :
  `static-site`, `static-site-https` (nginx, monit), `zfs-scrub` (monit) ne
  rechargent plus le service à chaque apply, seulement si une étape
  précédente de la recette a changé quelque chose. `monit` recharge désormais
  monit quand il réécrit `monitrc` (ce n'était pas fait). Évite les alertes
  « Monit instance changed » envoyées à chaque apply (2 par apply constatées
  sur qwerty le 6 oct.).
* `acme` — conventions du port FreeBSD `security/acme.sh` : utilisateur
  `acme` (plus root), home `/var/db/acme/.acme.sh` (où le paquet relie les
  plugins DNS — corrige « Cannot find DNS API hook for: dns_ovh »),
  certificats dans `/var/db/acme/certs`, `account.conf` tiré de l'exemple
  du port, renouvellement par `/usr/local/etc/cron.d/acme` (ligne du port :
  `lockf`, journal `/var/log/acme.sh.cronjob.log`), rotation par
  `newsyslog.conf.d/acme.sh.conf`, règle `sudoers.d/acme` limitée à
  `service nginx reload`. ⚠️ Un serveur déjà équipé de l'ancien schéma
  (home `/usr/local/etc/acme.sh`, cron de root) doit être migré.
* `monit` — mails en français : objet `[monit][<fqdn>] <service> ·
  <catégorie> · <état>` (catégories françaises par type d'événement :
  présence du service, ressources, connexion, contrôle, démarrage de monit,
  « alerte » sinon ; l'état reste celui de monit, non traduit) et corps en
  français (serveur, service, événement, action, date, détail).
  Charge rapportée au nombre de cœurs (`load_per_core`, défaut 1.5 ; avant :
  seuil fixe de 4). `sshd` et `cron` surveillés et relancés s'ils tombent.
  Un contrôle par minute (`poll_interval` 120 → 60 s : relance en moins
  d'une minute) ; charge, mémoire et swap alertent après 7 contrôles
  consécutifs (~7 min) pour ignorer les pics. Crée `/usr/local/etc/monit.d`
  (sinon `Include failed` à chaque démarrage tant que le dossier manque).
* `zfs-scrub` — planification de la sonde santé au format cron
  (`check_schedule`, défaut `*/30 * * * *`, une fois par demi-heure) au lieu
  de `every N cycles`, déprécié par monit 6.0 (avertissement constaté sur
  qwerty le 6 oct.). Remplace le paramètre `check_cycles`.
* `smtp-relay` — refaite selon les conventions du système de base : dma
  du système (MTA par défaut depuis FreeBSD 14) au lieu du paquet `dma`, dont
  `mailer.conf` pointait sur un `/usr/local/sbin/dma` inexistant (aucun
  courrier ne partait) ; config dans `/etc/dma/` en `root:mail` 0640 (auth
  lisible par dma, setgid mail) ; `mailer.conf` = exemple du système ; alias
  posés dans `/etc/mail/aliases` par `line-in-file` (`root:` et l'attrape-tout
  `*:` — le courrier de TOUS les utilisateurs part vers la destination), sans
  écraser les alias système ni le lien `/etc/aliases` ; `sendmail_enable=NONE`.
  Requiert beryl >= 0.6.26 (`line-in-file`).

=== Ajouté

* `static-site-https` — site statique en HTTPS (nginx-lite) : certificat
  Let's Encrypt validé par DNS-01 (`dns_ovh`, identifiants OVH du coffre,
  laissé dans `/var/db/acme/certs` selon le port ;
  aucune coupure, ni à l'émission ni aux renouvellements), HTTP → HTTPS,
  durcissement de `static-site` + HSTS, TLS 1.2/1.3, hôte inconnu → 444 en
  HTTP et HTTPS. Contrôle monit déposé dans `monit.d` (nginx relancé s'il
  tombe, alerte si le site ne répond plus en HTTPS ou si le certificat
  expire dans moins de 14 jours). À utiliser à la place de `static-site`.
* `static-site` — site web statique servi par `nginx-lite` sur le port 80
  (IPv4 + IPv6) : racine `/usr/local/www/{{ hostname }}` (propriétaire
  `deploy:www`), `nginx.conf` posé (`server_tokens off`, gzip,
  `try_files`), nginx démarré puis rechargé si la conf change. Le chemin
  HTTPS : voir `static-site-https`. Paramètres : `server_name` (défaut `{{ fqdn }}`),
  `root`, `owner`. Conf durcie : `server_tokens off`, délais courts,
  `client_max_body_size 1k`, GET/HEAD seulement (`limit_except`), fichiers
  cachés refusés, en-têtes `X-Content-Type-Options`, `X-Frame-Options`,
  `Content-Security-Policy: frame-ancestors`, `Referrer-Policy`,
  `Permissions-Policy`, serveur par défaut en `return 444` (hôte inconnu).
  Page de test « à supprimer » posée seulement si
  `index.html` est absent (`if_absent`, requiert beryl >= 0.6.26) : une
  vraie page n'est jamais écrasée.

==== Durcissement sshd en recettes unitaires + méta

Découpage du durcissement sshd en recettes atomiques testables seules
(banc QEMU `test-apply.sh`), composées par la méta `ssh-hardening`
(modèle « sets FreeBSD ») :

* `sshd-auth-keys-only` — auth par clé, pas de mot de passe (ex-contenu
  direct de `ssh-hardening`).
* `sshd-host-key-ed25519` — une seule clé d'hôte (ed25519).
* `sshd-crypto-modern` — kex/ciphers/MACs modernes calqués sur la
  référence adi.globex.example + `mlkem768x25519-sha256` (post-quantique,
  OpenSSH 10) ; zéro `[fail]`/`[warn]` ssh-audit, mitigation Terrapin
  totale (pas de chacha20-poly1305).
* `sshd-banner-neutral` — banner neutre : `VersionAddendum` = société
  (interpolation `{{ company }}`) → masque OS + date de patch.
* `ssh-hardening` devient une MÉTA pure (`requires` les 4 unités) ; plus
  de step `service-reload` (`sshd-config-set` valide + recharge sshd
  lui-même) → idempotente.
* `lib32`, `kernel-dbg` — sets pkgbase optionnels opt-in (`pkg-install`
  des méta-paquets `FreeBSD-set-lib32` / `FreeBSD-kernel-generic-dbg`),
  exclus de l'install de base pkgbase.

==== Phase 2 → 4 — Mesh Headscale, toggle port 22, hooks Capistrano

Suite directe des Phases 1a/1b ci-dessous : on dispose désormais du
parc Headscale prêt côté serveur, on enrôle les hosts dans le mesh,
on bascule sshd en overlay-only, et on prévoit un toggle d'urgence
pour les déploiements Capistrano legacy. Le tout exploite les 5
primitives ajoutées dans beryl v0.4.0.

* `headscale-node` (Phase 2) — joint un host au mesh.
  pkg-install tailscale, service-enable tailscaled, headscale-join
  (qui lit `HEADSCALE_AUTHKEY` posée par EnvFile depuis le coffre
  `secrets` de la société).
* `sshd-overlay-only` (Phase 3a) — bascule sshd en écoute uniquement
  sur l'IP tailscale du host. assert-tailscale-up en pré-check,
  ListenAddress résolu via `value_from_command: "tailscale ip -4"`,
  pf-rule block 22 public en défense en profondeur. À tester sur
  un host non-critique avant déploiement en série.
* `sshd-public-open` (Phase 3b) — ouvre TEMPORAIREMENT le port 22
  public. assert-env-var BERYL_REASON obligatoire,
  auto-close-schedule à 1 h, et chaque ouverture commit une ligne
  d'audit dans initech/headscale-state via
  headscale-state-commit.
* `sshd-public-close` (Phase 3b) — referme le port 22 public,
  repasse en overlay-only. Idempotent. Appelée manuellement par
  Capistrano ou automatiquement par le job at posé en ouverture.

==== Documentation (Phase 2bis + Phase 3c)

* `doc/headscale-setup.adoc` § Workflows CI : ephemeral nodes —

* `doc/headscale-setup.adoc` § ephemeral vs sshd-public-open —

* `doc/capistrano-ssh-window.rake` — fichier prêt à copier dans

  `before deploy:starting → initech:ssh_open` et
  `after deploy:finished/failed → initech:ssh_close`. Detection

  jusqu'à 60 s pour la propagation pf, raise sur timeout.

==== Phase 1a/1b — Headscale auto-hébergé (overlay réseau Initech)

Trois recettes et un document pour le déploiement Headscale décrit
dans la roadmap interne `roadmap_beryl_headscale.md`. Architecture :
1 actif (RBX) + 2 standbys chauds (SBG, GRA), état partagé via dump
SQL textuel commit toutes les 5 min sur le repo GitHub privé
`initech/headscale-state`.

* `headscale-server` — installe headscale + sqlite3, pose la config
  (écoute `127.0.0.1:8080`, TLS délégué à un nginx en frontal),
  ouvre 80/443 en pf, démarre le service. SQLite WAL activé pour
  permettre des snapshots `.backup` sans bloquer le service.
* `headscale-backup` — sur le primary : cron 5 min qui fait
  `sqlite3 .backup` → `.dump` → `gzip` → `git commit + push` vers
  `initech/headscale-state`. Sérialisé via `flock`, garde-fous
  sur pré-requis absents. Inclut un helper one-shot
  `headscale-backup-init.sh` pour le clone initial du repo.
* `headscale-standby` — sur SBG/GRA : installe headscale **mais
  garde le service éteint** (`service-disable`), pose un cron
  `git pull` toutes les 5 min, et un script `headscale-promote.sh`
  pour le failover manuel (restore SQL + activation service + log
  des étapes opérateur restantes).

==== Documentation

* `doc/headscale-setup.adoc` — procédure pas-à-pas pour le bootstrap

  ajout côté GitHub avec règle write-access primary uniquement,
  premier clone + premier snapshot, premier `git pull` standby) et
  procédure failover détaillée (~15-30 min RTO).
