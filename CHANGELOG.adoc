=== Ajouté

==== Phase 2 → 4 — Mesh Headscale, toggle port 22, hooks Capistrano

Suite directe des Phases 1a/1b ci-dessous : on dispose désormais du
parc Headscale prêt côté serveur, on enrôle les hosts dans le mesh,
on bascule sshd en overlay-only, et on prévoit un toggle d'urgence
pour les déploiements Capistrano legacy. Le tout exploite les 5
primitives ajoutées dans beryl v0.4.0.

* `headscale-node` (Phase 2) — joint un host au mesh.
  pkg-install tailscale, service-enable tailscaled, headscale-join
  (qui lit `HEADSCALE_AUTHKEY` posée par EnvFile depuis le coffre
  `secrets` de la société).
* `sshd-overlay-only` (Phase 3a) — bascule sshd en écoute uniquement
  sur l'IP tailscale du host. assert-tailscale-up en pré-check,
  ListenAddress résolu via `value_from_command: "tailscale ip -4"`,
  pf-rule block 22 public en défense en profondeur. À tester sur
  un host non-critique avant déploiement en série.
* `sshd-public-open` (Phase 3b) — ouvre TEMPORAIREMENT le port 22
  public. assert-env-var BERYL_REASON obligatoire,
  auto-close-schedule à 1 h, et chaque ouverture commit une ligne
  d'audit dans aloli-aloli/headscale-state via
  headscale-state-commit.
* `sshd-public-close` (Phase 3b) — referme le port 22 public,
  repasse en overlay-only. Idempotent. Appelée manuellement par
  Capistrano ou automatiquement par le job at posé en ouverture.

==== Documentation (Phase 2bis + Phase 3c)

* `doc/headscale-setup.adoc` § Workflows CI : ephemeral nodes —
  pattern recommandé pour les déploiements automatisés (GitHub
  Actions, GitLab CI...) : le runner devient un node Headscale
  temporaire, auto-purgé à la fin du job, port 22 jamais ouvert
  public. Inclut le pattern de pre-auth key reusable + ephemeral
  + le snippet workflow GitHub Actions de référence.
* `doc/headscale-setup.adoc` § ephemeral vs sshd-public-open —
  tableau de décision pour choisir entre les deux mécanismes.
* `doc/capistrano-ssh-window.rake` — fichier prêt à copier dans
  `lib/capistrano/tasks/` de l'app Rails legacy. Hooks
  `before deploy:starting → aloli:ssh_open` et
  `after deploy:finished/failed → aloli:ssh_close`. Detection
  préalable du port 22 (skip si déjà ouvert), boucle d'attente
  jusqu'à 60 s pour la propagation pf, raise sur timeout.

==== Phase 1a/1b — Headscale auto-hébergé (overlay réseau Aloli)

Trois recettes et un document pour le déploiement Headscale décrit
dans la roadmap interne `roadmap_beryl_headscale.md`. Architecture :
1 actif (RBX) + 2 standbys chauds (SBG, GRA), état partagé via dump
SQL textuel commit toutes les 5 min sur le repo GitHub privé
`aloli-aloli/headscale-state`.

* `headscale-server` — installe headscale + sqlite3, pose la config
  (écoute `127.0.0.1:8080`, TLS délégué à un nginx en frontal),
  ouvre 80/443 en pf, démarre le service. SQLite WAL activé pour
  permettre des snapshots `.backup` sans bloquer le service.
* `headscale-backup` — sur le primary : cron 5 min qui fait
  `sqlite3 .backup` → `.dump` → `gzip` → `git commit + push` vers
  `aloli-aloli/headscale-state`. Sérialisé via `flock`, garde-fous
  sur pré-requis absents. Inclut un helper one-shot
  `headscale-backup-init.sh` pour le clone initial du repo.
* `headscale-standby` — sur SBG/GRA : installe headscale **mais
  garde le service éteint** (`service-disable`), pose un cron
  `git pull` toutes les 5 min, et un script `headscale-promote.sh`
  pour le failover manuel (restore SQL + activation service + log
  des étapes opérateur restantes).

==== Documentation

* `doc/headscale-setup.adoc` — procédure pas-à-pas pour le bootstrap
  (création repo GitHub privé, génération deploy keys ed25519,
  ajout côté GitHub avec règle write-access primary uniquement,
  premier clone + premier snapshot, premier `git pull` standby) et
  procédure failover détaillée (~15-30 min RTO).

=== Modifié

==== Extensions typées

* Les recettes sont renommées `<nom>.recipe.yml` (au lieu de
  `<nom>.yml`). Le type est désormais explicite dans le nom, en
  cohérence avec la config beryl (`.host.yml` / `.domain.yml` /
  `.group.yml`). Voir beryl
  `docs/adr/ADR-015-typed-config-extensions.adoc`. Le champ `recipe:`
  devient facultatif (le nom est dérivé du fichier).

=== Ajouté

==== Recettes Aloli courantes

Composent les primitives livrées côté beryl (Phase 2 du moteur) :

* `ssh-hardening` — durcit sshd (PermitRootLogin prohibit-password,
  PasswordAuthentication no, KbdInteractive/EmptyPasswords/X11 no).
* `firewall-pf` — pf minimal et sûr (SSH autorisé, reste bloqué) ;
  opt-in, possède `/etc/pf.conf` (à ne pas combiner avec pf-rule).
* `ruby` — Ruby + Bundler.
* `nginx` — nginx + activation du service.
* `letsencrypt` — certbot + cron de renouvellement.
* `web-server` — agrégat (ruby + nginx + letsencrypt).
* `post-install` enrichi : ajoute `ssh-hardening` au socle.

==== Phase 1 — premières recettes (PoC)

* `base-packages` — packages de base (bash, git, curl) via
  `pkg-install`.
* `shell-tools` — zsh + tmux, `requires: [base-packages]`.
* `freebsd-updates` — installe `ca_root_nss` (prérequis HTTPS) ;
  le cron quotidien de check arrivera en Phase 2 avec la primitive
  `cron-entry`.
* `post-install` — recette agrégat minimale
  (`requires: [freebsd-updates, base-packages, shell-tools]`),
  prouve la résolution transitive + le tri topologique côté beryl.

==== Documentation

* README : statut passé en Phase 1 (PoC) ; chemins corrigés de
  `~/.beryl/` vers `~/.config/beryl/` (beryl suit désormais la spec
  XDG Base Directory).
